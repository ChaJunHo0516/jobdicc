# PreBridge 기획서 (P0 MVP 요구사항)

> **문서 상태**: 원본 기획서가 저장소에 없어서, 2026-11-05 개발 착수 요청문에 적힌 요구사항과 개발 원칙을 기준으로 작성한 초안이다.
> 원본 기획서를 받으면 이 문서와 대조해 빠진 요구사항을 보완한다. 요구사항은 임의로 삭제하지 않는다.

## 1. 서비스 개요
PreBridge는 **회사마다 독립된 AI 프리온보딩·직무교육·채용 통합 웹서비스**다.
개인은 한 계정으로 채용공고를 보고 지원할 수 있다. 합격하면 해당 회사의 학습공간에 들어가 입사 전 교육(프리온보딩)을 받는다.
회사는 자사 교육자료를 올리고, AI 요약과 퀴즈를 검토·승인한 뒤 구성원에게 공개한다.

## 2. 문제 정의
| # | 문제 | PreBridge의 해결 방향 |
|---|---|---|
| 1 | 합격자가 입사 전 회사·직무 정보를 체계적으로 받지 못한다 | 합격자 인증 후 회사 학습공간 접근, 진도 관리 |
| 2 | 교육자료가 흩어져 있고 부서·직급별로 볼 자료가 다르다 | 기업·부서·직급별 문서 접근 통제 |
| 3 | 교육담당자가 요약·평가 문항을 직접 만들기 어렵다 | AI 요약·퀴즈 자동 생성 + 담당자 검토 |
| 4 | AI 결과물을 검증 없이 쓰면 잘못된 정보가 퍼진다 | **승인 전 비공개**, 검토 상태 상시 표시 |
| 5 | 채용과 온보딩 시스템이 분리되어 있다 | 공고→지원→합격→초대→학습으로 이어지는 흐름 |
| 6 | 여러 회사가 같은 플랫폼을 쓰면 내부자료 유출이 우려된다 | 회사 간 데이터 격리를 서버에서 강제 |

## 3. 사용자 유형
- **개인 회원(지원자)**: 공고 조회, 입사지원, 본인 지원현황 조회, 초대 코드 등록
- **합격자(PRE_HIRE)**: 초대 코드로 인증한 입사 예정자. 허용된 학습자료 열람, 퀴즈 응시
- **직원(EMPLOYEE)**: 소속 회사의 허용된 학습자료 열람, 퀴즈 응시
- **교육담당자(TRAINER)**: 교육자료 업로드, 문서·AI 결과 검토와 승인, 진도 조회
- **회사 관리자(COMPANY_ADMIN)**: 위 권한 전체 + 구성원·부서·직급·초대·채용공고·지원자 관리
- **플랫폼 관리자(SUPER_ADMIN)**: 회사 개설 신청 승인. **회사 내부 자료는 볼 수 없음**

## 4. P0 기능 요구사항
| ID | 기능 | 수용 기준 |
|---|---|---|
| F1 | 개인 회원가입·로그인 | 이메일·비밀번호 가입, 비밀번호 정책, 세션 로그인·로그아웃, 로그인 시도 제한 |
| F2 | 회사별 독립 학습공간 | `/c/{회사}` 공간. 소속 구성원만 접근, 비소속자에게는 404 |
| F3 | 회사 관리자·교육담당자 계정 | 회사 개설 신청자가 관리자가 됨. 관리자가 교육담당자 역할 지정 |
| F4 | 합격자 인증·직원 권한 관리 | 1회용·만료되는 초대 코드(이메일 일치 필수), 합격자→직원 전환, 정지·해제 |
| F5 | 기업·부서·직급별 문서 접근 통제 | 문서마다 접근 규칙(부서, 직급 범위, 역할). 규칙이 없으면 학습자는 볼 수 없음 |
| F6 | 교육자료 업로드·승인 | PDF/TXT/MD, 최대 10MB, 업로드하면 승인 대기 상태. 승인한 문서만 공개 |
| F7 | AI 요약·퀴즈 생성 | 문서 텍스트로 요약·객관식 퀴즈 생성. **승인 전에는 학습자에게 보이지 않음** |
| F8 | 퀴즈 응시·학습 진도 | 서버 채점(정답은 클라이언트로 보내지 않음), 최고점·완료 여부, 회사 진도 현황 |
| F9 | 채용공고 등록·조회·마감 | 작성중/게시/마감 상태, 마감일 자동 마감, 공개 목록 |
| F10 | 입사지원·지원현황 | 중복 지원 금지, 마감 공고 지원 거부, 지원 철회, 회사측 상태 변경 |
| F11 | 회사 간 데이터 격리 | 모든 회사 데이터에 companyId를 두고 서버 계층에서 강제. 교차 접근 테스트 |
| F12 | 보안 테스트·오류 검증 | IDOR, 권한 상승, 승인 전 노출, 파일 업로드 공격 테스트 |

## 5. 개발 원칙
- 인증과 권한 검사는 모두 서버에서 한다. UI에서 메뉴를 숨기는 것은 보조 수단일 뿐이다.
- A회사와 B회사의 내부 자료가 섞이지 않게 한다.
- AI가 만든 자료는 관리자 승인 후에만 공개한다. 검증되지 않은 결과를 사실처럼 표시하지 않는다.
- 가상 기업과 샘플 데이터만 사용한다(알파테크, 베타로지스).
- 민감정보와 API 키는 환경변수(`.env`, git 제외)로만 관리한다.
- 기능마다 테스트를 작성하고, Phase가 끝날 때마다 문서화와 Git 커밋을 한다.
- 배포, 유료 API 실제 호출, 외부 시스템 연결은 별도 승인을 받는다.

## 6. 범위 밖 (P0 이후)
이메일 발송(초대 코드는 화면에 1회 표시), 외부 파일 스토리지, 실제 배포, SSO, 이력서 파일 첨부, 알림.
